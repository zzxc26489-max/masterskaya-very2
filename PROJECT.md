# Контекст проекта «Мастерская Веры»

Мастер-файл для быстрого входа. Обновлять при изменении данных.

---

## 1. Бизнес

**Что это:** авторские фигурки ручной работы из полимерной глины —
драконы, сказочные персонажи, лесные существа. Каждая — в единственном
экземпляре, со своей историей.

**Собственный язык бренда** (важно сохранять в текстах):
- «Жители» — фигурки/персонажи, не «товары»
- «Миры» / «коллекции» — тематические группы Жителей
- «Хроники» — истории уже проданных Жителей
- Обращение к посетителю — «путник»

**Контакт:** через форму на `/contact.html`, самый быстрый канал — Telegram.
Отвечает Вера лично.

## 2. Состояние сайта

Сайт уже полностью спроектирован и построен — не черновик, а готовый
продукт с продуманной атмосферой (тёмная тема, реальная предметная
фотосъёмка, авторские орнаменты, эффекты по мирам: снег, светлячки,
туман).

**Технически:** Node.js + Express (`studio/server.mjs`), не статический
сайт. Есть встроенная админка (`/admin`, пароль в `.env`) для управления
Жителями, коллекциями, историями, Хрониками, фото и видео — без правки
кода.

**Страницы:** Главная, Жители (`/residents.html`), Миры
(`/collections.html`), Как создаются (`/process.html`), О мастерской
(`/about.html`), Контакты (`/contact.html`).

**Данные:** `studio/data/content.seed.json` (Жители, коллекции, тексты) +
`studio/data/content.worlds.json` (картинки по мирам). Медиа —
`studio/public/media/`.

### Деплой

- **Локально:** `cd studio && npm install && npm run dev` → localhost:4173
- **Предпросмотр:** GitHub Pages из `.github/workflows/deploy-pages.yml`,
  собирает статический срез `studio/public` (без `/admin`) при пуше в
  `main`. Публично: https://zzxc26489-max.github.io/masterskaya-very2/
  (недоступен для проверки из этого окружения — прокси блокирует
  `*.github.io`, проверять через локальный запуск + скриншот)
- **Прод:** предполагается отдельный сервер с постоянным хранилищем
  (см. `studio/DEPLOY.md`) — Render-превью использует временную
  файловую систему, загруженное через админку может пропадать

## 2a. Язык бренда и понятность

Свой язык («Житель», «Мир», «Хранитель», «Хроника») — сильная сторона,
но новичок его не знает. Поэтому на главной есть секция **«Здесь у
вещей свои имена»**, которая расшифровывает все четыре слова. Правило:
**поэзию сохраняем, но каждое своё слово должно быть объяснено или
понятно из контекста.** Не заменять «Жителей» на «товары».

Статусы Жителя (`availability`) и что они значат покупателю:

| Статус | Подпись на сайте | Смысл |
|--------|------------------|-------|
| `available` | Можно приобрести | свободен, можно забрать |
| `in-progress` | В работе | ещё лепится |
| `reserved` | Уже выбрали | забронирован |
| `archive` | Нашёл Хранителя | продан |

Страница проданного Жителя **не тупик**: внизу блок «Что дальше» —
объясняет, что повторить нельзя (в этом и ценность), предлагает заказать
похожего и показывает свободных.

## 2b. Скорость загрузки (замерено 03.09.2026)

Замеры сделаны локально в Chromium через Playwright, экран 390px.

**Что было не так и что починено:**

1. **Шрифты блокировали отрисовку.** Первой строкой `site.css` стоял
   `@import` шрифтов с `fonts.googleapis.com`. Браузер должен был
   сначала скачать CSS, потом найти в нём импорт, потом сходить к
   Google и только потом рисовать. Теперь шрифты грузятся отдельной
   ссылкой в `<head>` и не задерживают отрисовку: текст сразу виден
   запасным шрифтом (Georgia / system-ui) и подменяется, когда
   основной доедет. Если Google Fonts вообще недоступен — сайт всё
   равно открывается за ~0,2 с.
2. **Движок частиц ронял FPS.** Каждая частица рисовалась с
   `shadowBlur` — самая дорогая операция canvas. На среднем телефоне
   сайт падал до **4 кадров в секунду**. Теперь свечение — заранее
   нарисованный спрайт: **60 FPS** на том же телефоне. Плюс: не
   больше двух живых слоёв одновременно, 36 кадров/с вместо 60,
   пиксельная плотность ограничена 1.5, старт отложен до
   `requestIdleCallback`, и есть автоспуск — если устройство всё
   равно не тянет, слой сам прореживается, а потом замирает.
3. **Телефоны качали десктопные фото.** Для каждого фото шире 900px
   рядом лежит копия на 800px (`имя-800.webp`), браузер выбирает её
   через `srcset`. Экономия ~3,9 МБ по сайту; главная на телефоне —
   вместо ~1 МБ фотографий около 0,4 МБ.

**Чем перегенерировать после добавления фото:** `npm run media:phone`
(нужен `sharp`; скрипт сам пересоберёт список в `assets/js/media.js`).

**Про «3 секунды».** Жёсткого правила «не открылся за 3 с — вниз
выдачи» нет. Google смотрит на Core Web Vitals, где «хорошо» для LCP
— **2,5 с**, и это один из многих сигналов, а не обрыв. Откладывать
эффекты на 10 секунд не нужно и вредно: эффекты и так стартуют после
отрисовки страницы, а таймер просто сделал бы сайт мёртвым на 10
секунд.

## 3. Как работать с этим проектом

- **Не переделывать без запроса.** Сайт уже сильный и цельный по
  дизайну — сюда приходят с конкретными задачами (тексты, SEO, баги,
  подготовка к запуску), а не с «сделай красиво».
- Тот же стек скиллов, что и у «Свой Сервис», можно скопировать при
  необходимости: `.claude/skills/` пока не заведена в этом репозитории.
- Известная мелочь: `npm install` в `studio/` подсвечивает 1
  high-severity уязвимость (`npm audit`) — не проверял детали, стоит
  глянуть перед боевым релизом.

### Уникальность Миров (сделано)

Каждый Мир теперь визуально свой — слой `worldAtmosphere(theme)`
(fixed, за контентом) + SVG-орнамент + цветовая заливка:

| Мир | Воздух | Орнамент |
|-----|--------|----------|
| Зимние легенды | падает снег | морозный кристалл |
| Тайны древнего леса | светлячки летают по всей странице | папоротник |
| Древние существа | дым и восходящие угли | чешуя + крыло |
| Русские сказки | искры от огня | гжельская роза на славянском плетении |
| Домашние легенды | пыль в солнечном луче | солнце на льняном переплетении |

Частицы генерируются seeded-RNG с индивидуальным вектором дрейфа —
поэтому летают хаотично, а не по одной траектории. Раньше светлячки
лежали плёнкой поверх фото Жителя; теперь основная масса — в воздухе
страницы, а на фото остаётся разреженная копия (`density .55`).

Тексты «фишек» Мира лежат в `WORLD_TRAITS` в `site.js` (кто живёт,
цвета, кому в подарок) — это дизайн-контент, не редактируется через
админку.
