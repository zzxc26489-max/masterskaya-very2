# Финальная система «Мастерская Веры»

Это самостоятельная версия сайта с публичной частью и админкой. Она не зависит от старых HTML-страниц в корне репозитория.

## Запуск

```bash
cd studio
cp .env.example .env
npm install
npm run dev
```

Откройте `http://localhost:4173`. Админка находится по адресу `http://localhost:4173/admin`.

## Что хранит админка

- Жителей, их фотографии, статусы, Хроники и галереи;
- коллекции и оформление Миров;
- истории Мастерской;
- входящие заявки на создание Жителя;
- фотографии и видео, загружаемые сразу в папку конкретного Жителя.

Для маленькой мастерской используется единый JSON-файл данных: он создаётся из `data/content.seed.json` при первом запуске. На сервере следует добавить `studio/data/content.local.json` и `studio/public/media/uploads/` в регулярное резервное копирование.

## Что заполняется через админку

- **Цены Жителей.** Если цены нет, на карточке честно стоит «Цена по
  запросу» — выдуманных чисел система не показывает нигде, включая
  разметку для поисковиков. Сейчас цена есть у 11 работ из 17.
- **Описание Мира** — короткая картина Мира, одна и та же на главной,
  на «Жителях» и на странице Мира.
- **Галерея Жителя.** Сейчас у 15 из 17 по одному кадру. Нужно 3
  ракурса + кадр в руке: по нему видно размер.
- **Отзывы с Авито** (раздел «Отзывы»). Переносятся руками: выгрузки у
  Авито нет. Имя, текст, оценка и дата — как в карточке на Авито,
  дословно. Пустой блок на сайте не показывается.
- **Ссылка на профиль Авито** (раздел «Настройки»). Появляется в
  подвале и в заголовке блока отзывов. Принимается только адрес,
  начинающийся с http:// или https://.

## Перед публикацией

1. Указать сильные `ADMIN_PASSWORD` и `SESSION_SECRET` в `.env`
   (локальный `vera-demo` — временный).
2. Настроить HTTPS и домен на Node.js-сервере.
3. Заменить плейсхолдер домена в тегах для поисковиков:
   ```bash
   sed -i 's#__SITE_ORIGIN__#https://реальный-домен#g' \
     public/*.html public/robots.txt public/sitemap.xml
   ```
4. Добавить реальные ссылки на Telegram / Instagram в настройках
   окружения или в отдельный блок контактов.
5. Не удалять старый сайт до проверки этой версии на телефоне и
   компьютере.

## Где что лежит в коде

Весь публичный сайт рисуется одним файлом — `public/assets/js/site.js`:
у каждой страницы своя функция (`home`, `residents`,
`collectionPage`, `chronicle` и т.д.), роутер внизу файла.

Стили идут четырьмя файлами, **порядок важен — выигрывает последний**:

```
fonts.css → site.css → home-redesign.css → site-fixes.css
```

`site-fixes.css` загружается последним и потому содержит большинство
правок. Если правка «не применилась» — первым делом проверьте порядок
подключения в `public/*.html`.

Версии в адресах (`site.js?v=20260916c`) — это сброс кэша. При правке
файла версию нужно поднять во **всех** `public/*.html`.
