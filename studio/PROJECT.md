## 2. Состояние сайта

Сайт полностью спроектирован и построен — не черновик, а готовый
продукт с продуманной атмосферой.

**Технически:** Node.js + Express (`studio/server.mjs`), **не статический
сайт**. Есть встроенная админка (`/admin`) для управления Жителями,
коллекциями, историями, Хрониками, фото и видео — без правки кода.

**Страницы:** Главная, Жители (`/residents.html`), Миры
(`/collections.html`), Мир (`/collection.html?world=<slug>`), Хроника
Жителя (`/chronicle.html?resident=<slug>`), Как создаются
(`/process.html`), О мастерской (`/about.html`), Контакты
(`/contact.html`), Создать Жителя (`/create.html`).

**Данные:** `studio/data/content.seed.json` (Жители, коллекции, тексты) +
`studio/data/content.worlds.json` (картинки по мирам).
Медиа — `studio/public/media/`.

### Как грузится контент (важно!)

`site.js` и `site-enhancements.js` сначала пробуют `/api/content`
(живой Express-сервер), при неудаче падают на `content.json`
(статический снимок). **Раньше выбор был завязан на проверку
`hostname.endsWith('.github.io')`** — из-за этого на любом другом
статическом хостинге (Beget и т.д.) сайт показывал ошибку
«Мастерская пока не открылась». Исправлено — теперь хостинг-агностично.

Единственное, что осталось привязано к `github.io` — переписывание
путей под подпапку (`rewritePreviewPaths`, `mediaUrl`), потому что
project-сайты Pages живут в `/<repo>/`. Это реальная особенность
именно GitHub Pages.

## 2a. Язык бренда и понятность

Свой язык — сильная сторона, но новичок его не знает. Поэтому на
главной есть секция **«Здесь у вещей свои имена»**, которая
расшифровывает Житель / Мир / Хранитель / Хроника.

**Правило: поэзию сохраняем, но каждое своё слово должно быть
объяснено или понятно из контекста.** Не заменять «Жителей» на
«товары».

Статусы Жителя (`availability`):

| Статус | Подпись на сайте | Смысл покупателю |
|--------|------------------|------------------|
| `available` | Можно приобрести | свободен, можно забрать |
| `in-progress` | В работе | ещё лепится |
| `reserved` | Уже выбрали | забронирован |
| `archive` | Нашёл Хранителя | продан |

Страница проданного Жителя **не тупик**: внизу блок «Что дальше» —
объясняет, что повторить нельзя (в этом и ценность), предлагает
заказать похожего и показывает до 3 свободных Жителей (сначала из
того же Мира).

## 3. Уникальность Миров

Каждый Мир визуально свой — слой `worldAtmosphere(theme)` (fixed, за
контентом) + SVG-орнамент + цветовая заливка:

| Мир | Воздух | Орнамент |
|-----|--------|----------|
| Зимние легенды | падает снег | морозный кристалл |
| Тайны древнего леса | светлячки летают по всей странице | папоротник |
| Древние существа | дым и восходящие угли | чешуя + крыло |
| Русские сказки | искры от огня | гжельская роза на славянском плетении |
| Домашние легенды | пыль в солнечном луче | солнце на льняном переплетении |

Частицы генерируются seeded-RNG с индивидуальным вектором дрейфа —
летают хаотично, а не по одной траектории. Раньше светлячки лежали
плёнкой поверх фото Жителя; теперь основная масса — в воздухе
страницы, а на фото разреженная копия (`density .55`).

На телефонах половина частиц скрывается через CSS (`:nth-child(2n)`) —
эффект тот же, нагрузка на GPU меньше.

Тексты «фишек» Мира — в константе `WORLD_TRAITS` в `site.js` (кто
живёт, цвета, кому в подарок). Это дизайн-контент, **через админку не
редактируется**.

## 4. Хостинг и деплой

### Аккаунт Beget

### ⚠️ Обычный (shared) хостинг Beget — Node.js НЕ поддерживает

Проверено по скриншотам панели: в настройках сайта только PHP
(версии 5.2–7.4, режим cgi, redis-сессии, редактор PHP-директив).
Раздела Node.js в панели нет. **На этом тарифе админка работать не
будет** — это ограничение тарифа, а не вопрос настройки.

Сейчас на `dmitrdwj.beget.tech` залит **статический снимок** сайта
(витрина без админки) — собирается так:

```bash
rm -rf /tmp/beget_site && mkdir -p /tmp/beget_site
cp -R studio/public/. /tmp/beget_site/
rm -rf /tmp/beget_site/admin
node studio/scripts/build-content.mjs \
  studio/data/content.seed.json \
  studio/data/content.worlds.json \
  /tmp/beget_site/content.json
cd /tmp/beget_site && zip -r /tmp/site.zip .
```

Архив распаковывается в `public_html`, `index.html` должен лежать
**в корне** папки, не во вложенной.

### План: VPS на Beget (для полноценного сайта с админкой)

Решение заказчика: **один общий VPS на все проекты** (Мастерская Веры
+ Свой Сервис). Настройка с компьютера по SSH.

- Тариф: 1 ядро / 1 ГБ / 10 ГБ NVMe — 11 ₽ в день (~330 ₽/мес)
- Регион: Россия, Санкт-Петербург
- Образ: **Ubuntu 26.04** (готовый шаблон Node.js искать не обязательно —
  Node ставится в 2 команды)

Порядок развёртывания:

```bash
ssh root@ВАШ_IP

# код
git clone https://github.com/zzxc26489-max/masterskaya-very2.git
cd masterskaya-very2/studio
npm install

# секреты (без них сервер в production не стартует — так задумано)
cp .env.example .env
openssl rand -hex 32     # результат → в SESSION_SECRET
nano .env
#   NODE_ENV=production
#   PORT=4173
#   ADMIN_PASSWORD=<длинный пароль>
#   SESSION_SECRET=<строка из openssl>

# запуск под PM2
pm2 start npm --name masterskaya-very -- run start
pm2 save
pm2 startup     # выполнить команду, которую он напечатает
```

Проверка: `http://ВАШ_IP:4173/` и `http://ВАШ_IP:4173/admin`.
Если не открывается — вероятно закрыт порт в файрволе Beget.

**Требование:** Node.js 20.6+ (из-за `--env-file-if-exists` в
`package.json`).

### Обновление сайта после моих правок

Один раз создать на сервере скрипт:

```bash
cat > ~/deploy.sh << 'EOF'
#!/bin/bash
set -e
cd ~/masterskaya-very2
git pull origin main
cd studio
npm install
pm2 restart masterskaya-very
echo "Готово: сайт обновлён"
EOF
chmod +x ~/deploy.sh
```

Дальше каждое обновление — одна команда: `~/deploy.sh`

**Данные Веры при этом не теряются:** всё, что она добавляет через
админку, лежит в `data/content.local.json` и `public/media/uploads/` —
оба в `.gitignore`, `git pull` их не трогает.

Нюанс: если правится `content.seed.json` (стартовые данные), на уже
работающем сервере это НЕ подтянется в живую базу — она живёт своей
жизнью после первого запуска. Обычные правки дизайна/текстов
интерфейса подтягиваются нормально.

### GitHub Pages (превью)

`.github/workflows/deploy-pages.yml` собирает статический срез
`studio/public` (без `/admin`) при пуше в `main`.
Живой адрес: https://zzxc26489-max.github.io/masterskaya-very2/

⚠️ Из среды Claude Code **проверить нельзя** — прокси блокирует весь
внешний интернет (`*.github.io`, `beget.com` и всё остальное, 403 на
CONNECT). Проверять через локальный запуск + Playwright с подменой
домена через `page.route()`.

## 5. Как работать с этим проектом

- **Не переделывать без запроса.** Сайт цельный по дизайну — сюда
  приходят с конкретными задачами.
- Ветка разработки: `claude/hello-bro-3jx20p`. Влитa в `main`.
- Проверка перед коммитом: `cd studio && npm run check`
- Тесты: `npm run studio:test` (нужен
  `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome`)
- **Известный флейк:** тест «no broken assets» виснет на
  `waitUntil: 'networkidle'` в песочнице — это не баг сайта,
  воспроизводится и на чистом коде.

### Приёмы проверки, которые сработали

- Мобильный аудит: Playwright на 375px по всем маршрутам — ловит
  горизонтальный скролл, битые картинки, кнопки <44px
- Проверка статической сборки: `page.route()` с подменой хоста на
  `beget.tech` / `github.io` — ловит хостинг-зависимые баги
- При замере «скрытых» блоков помнить: reveal-анимация длится 0.8s, а
  страница растёт от ленивых картинок — мерить после полного скролла
  до стабильной высоты + 1.4s

### Починенные баги (были в коде до этой сессии)

- reveal-анимация использовала `toggle()` — блоки исчезали обратно
  при прокрутке мимо. Теперь появляются один раз + `unobserve`.
- `contact()` и `chronicle()` не вызывали `enableAtmosphereMotion()` —
  их `[data-reveal]` блоки были невидимы навсегда.
- В лайтбоксе висел `<img>` без `src` — считался битой картинкой на
  каждой странице с галереей. Теперь создаётся при первом открытии.
- Кнопки были 43px при минимуме 44px для пальца.
- Заголовки Миров обрезались на 375px (нижняя граница clamp 67px).
- Фавикон был прописан абсолютным путём — 404 на GitHub Pages
  (сайт живёт в подпапке).
- Загрузка контента была завязана на `github.io` — на Beget сайт
  показывал бы ошибку вместо контента.
