# Мастерская Веры

Чистый репозиторий финальной версии сайта Мастерской Веры. В нём нет старого статичного сайта и ранних прототипов: только работающая система в папке `studio/`.

`studio/` — самостоятельный сайт для будущего сервера и собственного домена. Он включает:

- единый дизайн на всех публичных страницах и аккуратную мобильную шапку;
- Жителей, Миры-коллекции, Хроники, процесс и форму создания будущего Жителя;
- реальные фотографии работ Веры, разложенные по папкам Жителей;
- атмосферу каждого Мира: снег, светлячки, туман древних существ и авторский орнамент;
- кнопку прокрутки вверх;
- защищённую админку для Жителей, коллекций, историй, Хроник, фотографий, видео и заявок;
- готовую структуру для будущего 2D/3D-конфигуратора авторских серий.

## Как устроен сайт (сентябрь 2026)

Страниц шесть: **Главная**, **Жители** (`/residents.html`), **Как
создаются**, **О мастерской**, **Контакты** и страница отдельного
Жителя — **Хроника** (`/chronicle.html?resident=...`). Плюс страница
одного Мира (`/collection.html?world=...`), куда попадают из полосы.

Отдельной страницы со списком Миров **нет** — она дублировала
«Жителей». Миры показаны полосами: у каждой своя подложка, свой воздух
(снег, светлячки, угли, искры, пыль в луче) и кнопка «Войти в мир»,
которая ведёт сразу внутрь.

- **На главной** — по 4 работы в полосе Мира.
- **На «Жителях»** — по 6, дальше кнопка «Показать ещё». Сейчас она не
  показывается: в самом большом Мире 5 работ. Появится сама, когда
  Жителей станет больше.
- **Фильтры** над Жителями липнут под шапкой и раскрывают полосы
  целиком: «Можно приобрести» показывает всё, что можно приобрести.

Между полосами и в конце тёмных страниц идёт золотой разделитель —
он ставится только там, где тёмное встречается с тёмным и границу
иначе не видно.

## Что осталось сделать

**От Веры** (без этого сайт не запускается по-хорошему):

1. **Цены.** Проставлены у 11 работ из 17. У пяти «в работе» цены нет
   — там честное «Цена по запросу». Вписываются через админку.
   По словам заказчика цены **заниженные** — стоит обсудить.
2. **Фотографии.** У 15 из 17 Жителей в галерее один кадр. Нужно
   **3 ракурса + 1 кадр в руке** на каждого: по кадру в руке
   понятен размер.
3. **Размеры.** Сейчас их нет нигде на сайте, а это первый вопрос
   покупателя штучной вещи. Нужно измерить все 17 работ.
4. **Упаковка.** Фото упакованной работы и подарочных наборов —
   для блока «Церемония встречи». Сценарий видео упаковки отправлен
   отдельно.
5. **Сверка.** Все ли 17 Жителей на сайте реальны, верны ли статусы,
   нет ли работ, которых на сайте не хватает.
6. **Отзывы и ссылка на Авито.** Блок отзывов готов, но пустой:
   Авито не отдаёт отзывы автоматически, а выдумывать их нельзя.
   В админке → «Отзывы» перенесите руками те, что хотите показать
   (имя, текст, оценка, дата — как в карточке на Авито), а в
   «Настройках» вставьте ссылку на профиль. Пока отзывов нет, блок
   на сайте не появляется, и ссылки на Авито тоже нигде нет.

**Техническое, перед публикацией:**

1. **Домен не куплен.** Во всех тегах для поисковиков стоит
   заглушка `__SITE_ORIGIN__`. Когда домен появится — заменить
   одной командой:
   ```bash
   sed -i 's#__SITE_ORIGIN__#https://реальный-домен#g' \
     studio/public/*.html studio/public/robots.txt studio/public/sitemap.xml
   ```
2. **Пароль админки** в `.env` временный (`vera-demo`) — сменить на
   длинный при переезде на постоянный сервер.
3. **Отзывы** отложены — появятся позже вместе с Авито.

Подробный технический контекст — в [PROJECT.md](PROJECT.md) и
[studio/PROJECT.md](studio/PROJECT.md) (раздел 9 — что именно
изменилось в редизайне).

Запуск локально:

```bash
cd studio
cp .env.example .env
npm install
npm run dev
```

Публичный сайт: `http://localhost:4173`.

Админка: `http://localhost:4173/admin`.

В локальной разработке временный пароль — `vera-demo`; перед публикацией его обязательно нужно заменить через `.env`.

Подробности о серверной публикации — в [studio/DEPLOY.md](studio/DEPLOY.md).

## Временный предпросмотр

Для проверки сайта до покупки домена и сервера можно создать временную ссылку в Render. Он будет автоматически пересобирать сайт после каждого изменения в ветке `main`.

1. Откройте [Deploy to Render](https://render.com/deploy?repo=https://github.com/zzxc26489-max/masterskaya-very2).
2. Войдите через GitHub и подтвердите создание сервиса.
3. В поле `ADMIN_PASSWORD` задайте собственный временный пароль для админки.
4. Дождитесь окончания первой сборки и откройте выданный адрес `*.onrender.com`.

Временный бесплатный сервис подходит для просмотра и тестов. Его файловая система не постоянная, поэтому добавленные через админку материалы и данные могут исчезнуть после перезапуска или новой сборки. Финальный сайт будет размещён на сервере с постоянным хранилищем.

## Тесты

```bash
npm run studio:check
npm run studio:test
```

GitHub Actions проверяет сервер, админку и адаптивные маршруты. Chromium для браузерных тестов устанавливается автоматически.
